Buildkite Pipelines is a CI/CD service with a hybrid design: Buildkite runs the control plane (the web interface, APIs and scheduling), and the jobs run on agents, either on your own machines or on agents Buildkite hosts. Your code stays on GitHub, GitLab or Bitbucket. Diffinery is a git forge with CI built in: it hosts your repositories, pull requests and issues, and runs GitHub Actions workflows as they are on its own runners. It is free, open-source software (Apache-2.0) that you deploy to your own Cloudflare account, with no hosted service (see [Deploy your own Diffinery](/docs/self-hosting/deploy) and the [source code](https://diffinery.com/codician/diffinery)). Buildkite facts here are from its own website and documentation, checked on October 25, 2026, and linked below.

## In short

- **The biggest difference is who runs the machines.** Buildkite is built around agents on your own infrastructure, which keeps your source code and secrets inside your network. Diffinery runs every job on hosted runners that your instance starts in Cloudflare Containers on your own Cloudflare account, unless you add self-hosted ones; there are no build machines to manage.
- **Choose Buildkite** if you want builds on your own fleet at large scale, need hosted macOS or machines larger than 4 vCPUs, want pipelines generated by code while a build runs, want SOC 2 Type II today, or want to keep your current Git host.
- **Choose Diffinery** if you don't want to manage build machines or a separate CI service, are happy to run your own instance on Cloudflare, want code hosting, review and CI in one product, write workflows as GitHub Actions YAML, and want AI agents held to guardrails by the forge itself.

## Where each one is the better fit

**Buildkite is the better fit when** you already run, or want to run, your own build machines, for example for security, special hardware or cost at very high volume; when source code and secrets must stay inside your network; when you need hosted macOS or machines larger than 4 vCPUs; when your pipelines are big enough that generating steps from code pays off; or when you want to keep GitHub, GitLab or Bitbucket. Buildkite's hosted agents and control plane are also run for you, where a Diffinery instance is yours to deploy and update.

**Diffinery is the better fit when** you want CI without managing any build machines, one platform for code, review and CI, workflows in the GitHub Actions format with actions from GitHub as they are, and a forge that enforces what AI agents can and can't do, and you're happy to run that forge on your own Cloudflare account. Your CI should be Linux, or you should be happy to add self-hosted runners for the rest.

## Moving from Buildkite

Deploy your own instance first ([guide](/docs/self-hosting/deploy)). Diffinery's importer reads from GitHub. If your code is on GitHub, it brings over each repository with its history, issues, pull requests, reviews and releases; see [Migrate from GitHub](/docs/migrate-from-github). From GitLab or Bitbucket, push branches and tags with plain Git; see [Move with plain Git](/docs/migrate-from-github#move-with-plain-git). Then rewrite each Buildkite pipeline as workflows in `.github/workflows/`. Jobs that need your own hardware can keep it: register those machines with `diffinery runner` and target them with `runs-on: [self-hosted, ...]`. See [Self-hosted runners](/docs/actions/runners#self-hosted-runners).

## Frequently asked questions

### Is Diffinery a Buildkite alternative?

Yes, if you're willing to move your repositories as well. Diffinery's CI runs on its own repositories, so it replaces Buildkite and your Git host together. Like Buildkite, it can run jobs on your own machines, with `diffinery runner`; unlike Buildkite, it also runs every Linux job on hosted runners in your Cloudflare account by default.

### Can I run my Buildkite pipelines on Diffinery?

No. Diffinery runs GitHub Actions workflows, not Buildkite pipeline YAML, and Buildkite plugins don't run on it. Teams moving from Buildkite rewrite their pipelines as workflows. Pipelines that generate their steps at build time map most closely to GitHub Actions matrices whose values come from an earlier job's outputs.

### Can Buildkite run GitHub Actions workflows?

In public preview. Buildkite's GitHub Actions Compatibility runs supported workflows from `.github/workflows/` as Buildkite jobs, with limits: no `pull_request_target`, no `workflow_run` or `repository_dispatch` yet, and no reproduction of GitHub's runner images ([source](https://buildkite.com/docs/pipelines/migration/run-github-actions-workflows)). On Diffinery, GitHub Actions is the native format.

### Can I use Buildkite with Diffinery?

Buildkite's documented source control integrations are GitHub, GitLab and Bitbucket, and Diffinery isn't one of them. On Diffinery, jobs run on your instance's hosted runners in Cloudflare Containers or on your own machines with `diffinery runner`.

### Is Diffinery cheaper than Buildkite?

Diffinery itself is free and open source; you pay Cloudflare for what your instance uses, which depends on your usage, so we don't quote a per-minute figure to compare. Buildkite charges per active user on Pro ($30 a month) plus hosted minutes at $0.004 per vCPU minute, or $3.50 a month per self-hosted agent after the first 10; with your own agents you also pay for the machines.

### Which is faster, Diffinery or Buildkite?

We haven't benchmarked Buildkite and don't quote others' numbers as our own. With self-hosted agents, Buildkite's speed depends mostly on the machines you give it. Diffinery's measured stage times are on the [Performance](/performance) page.
